## 1. 计划概述

### 1.1 本期范围（阶段一：网页版）【已全部交付，并超额完成】

- 从零创建 React + TypeScript + Vite 工程，配置 Tailwind CSS、TypeScript、组件体系；
- 数据层、逻辑层、状态层、平台适配层、组件层按架构分层落地；
- 纯逻辑单元测试；
- 全部界面与交互实现，遵循统一设计语言；
- 生产构建、产物生成、浏览器渲染与功能走查；
- 发布到 GitHub Pages，公网可访问；
- **超额交付**（原列为阶段二 / 后续迭代，实际已在网页版完成）：真实音频播放与本地曲库导入、收藏 / 历史 / 主题 / 歌单持久化、内嵌标签解析、液态玻璃改版、音乐库 / 自建歌单 / 播放队列 / 设置页。详见 §2.2 版本进展。

### 1.2 不在本期交付

- Windows 桌面安装包、达到上架级质量标准的手机 App（阶段二 / 三，不实际发布）；
- 账号、云同步、在线内容等服务端功能（产品定位明确不做）。

### 1.3 执行原则

1. **小步交付**：每个阶段产出可编译、可验证的中间结果，不一次性重写全部代码。
2. **先抽逻辑、再拆组件**：先把可独立测试的纯逻辑收口，再实现界面，降低风险。
3. **每步可验证**：每个任务标注验证方式；改动相关模块只跑相关测试，全部完成后做一次全量回归。
4. **不破坏需求闭环**：实现期间保持 PRD 定义的功能行为一致。
5. **发布须授权**：GitHub Pages 发布为对外行为，执行前取得明确同意。
6. **版本不写死**：工具与依赖版本在搭建时按当前可用稳定版确定，以实测为准。
7. **按需依赖**：只安装实际用到的库，避免重复功能库。

### 1.4 环境前提

- Node.js 与包管理器可用；
- 现代浏览器（用于渲染验证）；
- 可用 GitHub 仓库（用于 Pages 发布）；
- 具体工具与版本在搭建时按当前可用版本确定，不在本文写死。

### 6.2 回归策略

- 每完成一个模块，只跑该模块相关测试与类型检查，不跑全量；
- 全部模块完成后，执行一次全量类型检查 + 全量单测 + 构建 + 浏览器走查；
- 搭建前后保留界面对照截图，确认视觉与交互无回退；
- 发布前在本地环境完整验证，避免把问题带到公网。

## 7. 风险与应对

| 编号 | 风险 | 概率 | 影响 | 应对措施 |
| --- | --- | --- | --- | --- |

| R-07 | 依赖引入冗余导致包体积过大 | 低 | 首屏偏慢 | 按需引入；不引入功能重复库；构建后核对体积 |

### 7.1 阻塞条件

- 若构建持续失败：停止加功能，先定位依赖 / 配置问题，不在错误未明时反复盲试；
- 若本地 / 公网加载失败：保留浏览器控制台错误，定位路径、base 配置或产物缺失，修复后重新生成；
- 若未取得发布授权：停在 M6 的 6.5 之前，不执行任何对外推送。
