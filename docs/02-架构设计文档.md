## 1. 架构目标与设计原则

### 1.1 要解决的问题

播放器类项目最常见的结构问题，是把状态定义、界面组件、业务逻辑、平台 API 调用揉进同一文件，导致新增视图或切换平台时多处改动、文件膨胀。本架构在起步阶段即分层，并针对「网页 → 桌面 → 移动」的演进目标，把平台差异隔离在适配层，避免后续推翻重写。

### 1.2 设计目标

1. **分层清晰**：数据 / 逻辑 / 状态 / 组件 / 平台适配 / 宿主胶水分层，依赖单向向下。
2. **模块收口**：同类职责集中（播放状态机、歌词定位、主题映射），跨模块只通过明确接口交互。
3. **低耦合**：组件不直接调用平台 API；业务逻辑不写在组件渲染函数里。
4. **可演进**：本期纯网页，阶段二 / 三引入 Tauri 时，改动限制在平台适配层与构建配置，界面与逻辑不动。
5. **可测试**：纯逻辑用 TypeScript 函数实现，可在 Node 环境独立单元测试，不依赖浏览器与 UI 框架。
6. **避免过度设计**：不引入事件总线、依赖注入容器等多余抽象；以当前规模够用为限，预留替换点。

### 1.3 设计原则

| 原则 | 落地方式 |
| --- | --- |
| 单向依赖 | 上层依赖下层，下层不反向依赖上层；组件之间不互相直接调用 |
| 状态集中、视图只读 | 播放 / 导航 / 收藏等状态收口到 Zustand store，组件通过 selector 读取、通过 action 触发 |
| 逻辑与视图分离 | 切歌策略、歌词定位、时间格式化等纯计算放 `lib/`，可独立单测 |
| 平台差异隔离 | 计时、音频、文件系统等平台相关调用收口到 `platform/`，组件不感知运行平台 |
| 显式接口 | 模块间传递类型化的数据结构与函数签名，不共享可变全局状态 |
| 小文件、单一职责 | 单个源文件聚焦一类组件或一类逻辑，控制在易读规模 |

## 2. 总体架构

### 2.1 分层视图

```
┌──────────────────────────────────────────────────────────┐
│  宿主胶水层   应用入口 / 全局样式注入 / 定时器挂载          │  src/main.tsx, App.tsx
├──────────────────────────────────────────────────────────┤
│  组件层（Components）                                     │
│  主页 / 搜索 / 发现 / 我的 / 导航 / 迷你条 / 播放器 / 歌词   │  src/components/…
├──────────────────────────────────────────────────────────┤
│  状态层（Store）                                          │
│  Zustand slices：播放 / 导航 / 收藏 / 主题 / 搜索 / 历史     │  src/store/…
├──────────────────────────────────────────────────────────┤
│  业务逻辑层（Lib / Domain）                                │
│  播放状态机、切歌策略、歌词定位、搜索过滤、时间格式化、主题映射 │  src/lib/…
├──────────────────────────────────────────────────────────┤
│  数据层（Data）                                            │
│  类型定义、示例数据、只读查询函数                            │  src/data/…
├──────────────────────────────────────────────────────────┤
│  平台适配层（Platform）                                    │
│  计时 / 音频 / 文件系统 抽象；本期 Web 实现，后期 Tauri 实现   │  src/platform/…
└──────────────────────────────────────────────────────────┘

阶段二 / 三新增（本期留空）：
┌──────────────────────────────────────────────────────────┐
│  Tauri 壳 + Rust 核心                                     │
│  commands（IPC）/ 音频引擎 / 解码 / 媒体库 / 系统媒体控制     │  src-tauri/src/…
└──────────────────────────────────────────────────────────┘
```

### 2.2 依赖方向

```
main.tsx → App.tsx → components/* → store → lib → data
                          │           │
                          └───────────┴──→ platform（通过接口调用，不反向依赖上层）
```

- 组件只依赖 store 暴露的 selector 与 action，不直接调用平台 API；
- `lib/` 不引用 React 组件、不引用平台 API，只处理纯数据与纯计算；
- `data/` 不依赖上层任何类型；
- `platform/` 提供统一接口，由 store / 宿主调用；组件不感知当前运行平台；
- 阶段二 / 三的 Tauri commands 实现 `platform/` 接口，界面与逻辑无需改动。

### 2.3 数据流（单向）

```
用户事件（点击 / 输入 / 定时器）
        │
        ▼
组件事件处理器 → 调用 store action（如 play(idx)、toggleLike(id)、next()）
        │
        ▼
store 更新状态（cur / playing / pos / mode / liked …）
        │
        ▼
组件经 selector 订阅状态 → 按需重渲染
        │
        ▼
lib 纯函数被调用，产出计算结果（当前歌词行、过滤列表、进度百分比、切歌目标）
        │
        ▼
platform 执行副作用（计时、主题变量注入；后期音频控制），组件不直接操作平台
```

- 状态变化是视图更新的唯一来源；组件不直接改写彼此状态；
- selector 细粒度订阅，避免无关组件随状态变化重渲染；
- 副作用收口到 platform，按平台提供不同实现。

### 2.4 多端复用边界（三阶段关键）

| 层次 | 网页端（阶段一） | 移动端（阶段二） | 桌面端（阶段三） | 复用情况 |
| --- | --- | --- | --- | --- |
| data / lib | 完全一致 | 完全一致 | 完全一致 | 100% 复用 |
| store | 一致 | 一致 | 一致 | 复用 |
| components | 一致 | 触控 / 尺寸适配 | 一致 | 大部分复用 |
| platform 实现 | Web 实现 | Capacitor 实现（原生播放插件） | Tauri 实现 | 按端替换 |
| 宿主 / 打包 | Vite 静态产物 | Capacitor + APK | Tauri Desktop + 安装包 | 按端替换 |

> 设计收益：阶段二 / 三主要新增 platform 的 Capacitor / Tauri 实现与打包配置，组件与核心逻辑不变（移动端仅做触控 / 尺寸适配）。
>
> 路线修订（1.5.0 审计 A-58）：阶段二手机 App 曾评估 Tauri Mobile，未采用——息屏后台播放缺现成原生播放插件，定案改走 Capacitor（详见第二阶段路线调研记录）；阶段三桌面端仍为 Tauri。

## 4. 状态设计

### 4.1 Store 结构

状态集中在 Zustand store，按领域划分为多个 slice，逻辑上分片、运行时合一：

```ts
// 概念示意：具体类型以 store/types.ts 为准（v4 按 0.6.1 实际结构修订）
interface AppState {
  // 导航与界面（uiSlice）
  tab: Tab;                 // 'home' | 'search' | 'explore' | 'me'（explore 展示名为「音乐库」）
  playerOpen: boolean;
  lyricOpen: boolean;
  query: string;
  libraryView: 'songs' | 'albums' | 'artists' | 'playlists';
  libraryDetail: { kind: 'album' | 'artist' | 'playlist'; key: string } | null;
  sortKey: 'addedAt' | 'name' | 'artist';
  sortDir: 'asc' | 'desc';
  menuTrack: number | null; // 单曲菜单目标
  queueOpen: boolean;
  mePage: 'favorites' | 'history' | 'settings' | null;

  // 播放（playerSlice）
  cur: number;              // 当前曲目索引
  playing: boolean;
  pos: number;              // 当前进度（秒）
  mode: PlayMode;           // 'list' | 'repeat' | 'shuffle'
  audioError: string | null;
  queue: number[];          // 播放队列：曲目下标排列（不重复）
  queuePos: number;         // 当前曲目在队列中的位置

  // 集合（collectionSlice）
  tracks: Song[];           // 统一曲目源（用户导入，启动时从 IndexedDB 恢复）
  liked: Set<number>;       // 收藏曲目 id 集合
  history: number[];        // 最近播放索引序列
  playlists: Playlist[];    // 自建歌单

  // 外观（themeSlice）
  themeIdx: number;
}
```

> 说明：Zustand 的 selector 支持细粒度订阅，组件只订阅所需字段，避免无关重渲染。动作与状态同处 store，但组件只经动作变更状态，不直接写入多个字段。

### 4.2 状态分类

| 类别 | 状态 | 说明 |
| --- | --- | --- |
| 导航态 | `tab` | 当前主视图 |
| 播放态 | `cur`、`playing`、`pos`、`mode`、`audioError` | 当前曲目、是否播放、进度、模式、引擎错误 |
| 队列态 | `queue`、`queuePos` | 播放顺序（会话态，不持久化） |
| 收藏态 | `liked` | 收藏 id 集合（localStorage 持久化） |
| 歌单态 | `playlists` | 自建歌单（localStorage 持久化） |
| 外观态 | `themeIdx` | 当前主题索引（localStorage 持久化） |
| 覆盖层态 | `playerOpen`、`lyricOpen`、`queueOpen`、`menuTrack` | 播放器 / 歌词页 / 队列 / 单曲菜单 |
| 二级页态 | `libraryDetail`、`mePage` | 音乐库详情页、「我的」二级页 |
| 输入态 | `query` | 搜索关键词 |
| 历史态 | `history` | 最近播放索引序列（localStorage 持久化） |

### 4.3 派生状态（Selector / useMemo）

由基础状态派生、可被多个组件读取的计算值，用 selector 或 `useMemo` 缓存，避免重复计算：

| 派生值 | 来源 | 计算 |
| --- | --- | --- |
| 当前曲目 | `cur` | 从曲目集合按索引取值 |
| 当前歌词行 | `cur`、`pos` | `lib/lyric::lyricIndex` |
| 搜索结果 | `query`、曲目集合 | `data/query::search` |
| 进度百分比 | `pos`、当前曲目时长 | `lib/format::percent` |
| 是否已收藏当前曲 | `liked`、当前曲目 id | 集合包含判断 |

### 4.4 动作（Actions）

状态变更统一收口到 store 动作，组件只调用动作：

| 动作 | 输入 | 状态变更 | 调用逻辑 |
| --- | --- | --- | --- |
| `play(idx)` | 曲目索引 | `cur=idx`、`pos=0`、`playing=true`、写入历史、打开播放器 | 历史去重插入 |
| `togglePause()` | — | 翻转 `playing` | — |
| `next()` | — | 按模式计算下一索引，`pos=0` | `lib/player::nextIndex` |
| `prev()` | — | 上一索引（环形），`pos=0` | `lib/player::step` |
| `cycleMode()` | — | 模式在 List / Repeat / Shuffle 间轮换 | — |
| `toggleLike(id)` | 曲目 id | 收藏集合增删 | — |
| `seek(sec)` | 秒数 | `pos=sec` | 歌词时间戳解析 |
| `setTab(tab)` | 视图枚举 | 切换 `tab` | — |
| `setTheme(idx)` | 主题索引 | 更新 `themeIdx` | `lib/theme` 生成变量 |
| `setPlayerOpen(bool)` | 布尔 | 播放器覆盖层开关 | — |
| `setLyricOpen(bool)` | 布尔 | 歌词页开关 | — |
| `setQuery(str)` | 字符串 | 更新搜索关键词 | — |
| `play(index, context?)` | 曲目下标 + 可选列表上下文 | 建队列、切当前曲、记历史、同步引擎 | `lib/queue` 定位 |
| `applyAudioPos(sec)` | 引擎进度回调 | 写入 `pos` | — |
| `handleTrackEnd()` | 引擎 ended 回调 | 按模式在队列内收尾 | `lib/player` 步进/随机 |
| `playNext/enqueue/removeQueueAt/moveQueue/clearQueue` | 队列操作 | 维护 `queue/queuePos` 不变量 | `lib/queue` |
| `removeTrack(index)` | 曲目下标 | 删歌全量连带清理（状态侧） | `lib/queue` 重映射、`lib/playlists` 清理 |

> 设计要点：动作是状态变更的唯一入口。后续接入真实音频或持久化时，只需在动作内增加适配调用，组件签名不变。

### 5.5 平台适配层

**`platform/index.ts`**：定义平台能力接口。

```ts
export interface StyleAdapter {
  applyTheme(vars: Record<string, string>): void;
}

export interface AudioEngine {
  play(src: string): Promise<void>;
  pause(): void;
  seek(sec: number): void;
  position(): number;
  onProgress(cb: (sec: number) => void): void;
  onEnded(cb: () => void): void;
  onError(cb: (message: string) => void): void;
}
```

- **阶段一（已实现）**：`AudioEngine` 由 `platform/web.ts` 以 HTMLAudioElement 实现，事件经 `store/bootstrap.ts` 绑定进 store（进度 → `applyAudioPos`、结束 → `handleTrackEnd`、错误 → `audioError`）；`StyleAdapter` 写入 CSS 变量。v3 的 `Ticker` 模拟计时已删除；
- **持久化适配**：`platform/idb.ts`（IndexedDB 曲目记录）与 `platform/prefs.ts`（localStorage 原始读写）同属平台层，序列化规则在 `lib/prefs` / `lib/playlists`，落盘时机由 bootstrap 的订阅统一管理；
- **阶段二（手机 App）**：`AudioEngine` 改由 Tauri command + Rust 音频引擎实现；文件选择 / 权限走 Tauri 能力；持久化可由文件系统实现替换同接口；
- **阶段三（Windows 桌面）**：复用 `AudioEngine`；补充桌面文件系统访问；
- 组件与 `lib/` 只依赖接口，替换实现不动上层。

- 不在组件里直接调用平台 API；平台副作用走 `platform/` 与 hooks；
- 可复用 UI 原语（Button / Slider / Dialog 等）从 `components/ui/` 引入，源码自有、统一维护。

### 5.7 基础组件策略（shadcn 风格）

- 采用「源码复制进项目」的分发方式：从组件注册表复制 Button、Slider、Dialog、Tabs 等基础组件源码到 `components/ui/`，作为项目自有代码维护；
- 底层交互原语基于 Radix（无障碍、键盘支持），视觉由 Tailwind 令牌统一控制；
- 优势：源码可控、易定制、无黑盒依赖；代价：升级需手动同步差异，接受此代价以换取可控性；
- 依赖控制：只引入实际用到的组件源码，不整包引入。

## 6. 关键交互时序

### 6.1 点击曲目播放

```
SongRow.onClick
  → store.play(idx, context?)
      ├─ 以 context（所在列表顺序）重建 queue，queuePos 定位 idx
      ├─ history 去重插入 idx
      ├─ cur=idx, pos=0, playing=true
      └─ syncEngine：引擎播放 tracks[cur].audioSrc
  → 列表外层 onClick 打开 PlayerView；MiniBar 随状态重渲染
```

### 6.2 进度推进与播完收尾（引擎事件驱动）

```
AudioEngine timeupdate（platform/web）
  → bootstrap 绑定 → store.applyAudioPos(sec) → pos 更新（歌词高亮/进度条随之刷新）

AudioEngine ended
  → store.handleTrackEnd()
      ├─ repeat  → 引擎 seek(0) 重播
      ├─ list    → 队列内步进 +1（环形），cur 更新，syncEngine
      └─ shuffle → 队列内随机位置，cur 更新，syncEngine
```

### 6.3 搜索过滤

```
SearchView 输入 → store.setQuery(str)
  → useMemo 调用 data/query.search(songs, query)
  → 结果列表渲染为 SongRow
```

### 6.4 主题切换

```
MeView 点击主题 → store.setTheme(idx)
  → themeIdx 更新
  → useTheme 调用 lib/theme 生成变量 → platform.StyleAdapter 写入根元素 CSS 变量
  → 界面配色随变量变化
```

## 7. 主题与视觉系统实现

### 7.1 令牌分层

| 层级 | 载体 | 内容 |
| --- | --- | --- |
| 语义令牌 | CSS 变量（`--accent` 等） | 主题相关颜色，运行时可切换 |
| 静态令牌 | Tailwind 配置 | 间距刻度、圆角档位、字号、动效时长与缓动 |
| 组件样式 | Tailwind 工具类 | 引用令牌组合出组件外观，不写死魔法值 |

### 7.2 主题应用流程

1. `lib/theme` 根据当前主题产出 `{ '--accent': ..., '--bg': ..., '--bg-end': ... }`；
2. `platform.StyleAdapter.applyTheme` 将上述变量写入根元素；
3. 所有强调元素（进度条、收藏态、导航高亮、氛围光）引用 `var(--accent)`，自动同步变色；
4. 主题切换为纯前端状态变化，不触发页面刷新。

### 7.3 动效规范实现

- 时长与缓动令牌集中在 Tailwind 配置，组件统一引用；
- 唱片旋转、进度线、覆盖层转场优先使用 `transform` / `opacity`；
- `useTheme` 与组件读取系统「减少动态效果」偏好，命中时降级为无动画。

## 9. 错误处理与健壮性

| 场景 | 处理策略 |
| --- | --- |
| 曲目索引越界 | `byIndex` 返回 `undefined`，视图兜底取首曲或空态 |
| 时间戳解析失败 | `toSeconds` 返回 0，不抛异常 |
| 时长为 0 | 进度百分比分母取 `Math.max(dur, 1)`，避免除零 |
| 音频播放失败 | 引擎 onError → `audioError` 状态，界面提示且 `playing` 回落为 false |
| 标签解析失败 / 文件损坏 | 整体回退文件名推断，不阻断导入 |
| 本地存储不可用（隐私模式等） | platform 层静默降级为不持久化，功能照常 |
| 歌单 / 偏好落盘数据损坏 | lib 清洗函数丢弃非法条目，返回空集合，不崩溃 |
| 运行时异常 | 错误边界组件捕获，展示友好提示；控制台保留完整日志 |
| 空搜索结果 | 列表区展示空态提示 |
| 资源加载失败 | 发布页提供降级提示（建议现代浏览器），不出现白屏无反馈 |

### 10.1 阶段二 / 三（不改变架构分层）
